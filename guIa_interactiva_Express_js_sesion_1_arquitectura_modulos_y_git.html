2. Fundamentos de Express.js, Middlewares y Variables de Entorno

Conceptos clave desglosados desde cero para comprender cómo funciona el ciclo de vida de una petición HTTP en Node.js.

⚡

¿Qué es Node.js y por qué Express.js?

Node.js es un entorno de ejecución de JavaScript del lado del servidor impulsado por el motor V8. Express.js es el framework web minimalista más popular sobre Node, encargado de simplificar la creación de APIs REST estructurando rutas, peticiones y respuestas.

📦

Prerrequisitos y npm

Requerimos Node.js instalado (versión LTS), el cual incluye npm (Node Package Manager) para gestionar las librerías del proyecto.

# Verificar instalación

node -v && npm -v

🔄

¿Qué es un Middleware en Express?

Un Middleware es una función que tiene acceso al objeto de petición (req), al objeto de respuesta (res) y a la siguiente función middleware en el ciclo de la aplicación (next).

Actúan como filtros o pasillos de procesamiento intermedio. Por ejemplo: validar si un usuario está autenticado, registrar en consola cada petición HTTP que llega (logging), o transformar el cuerpo de la petición a formato JSON (express.json()).

// Ejemplo de Middleware personalizado

const miMiddleware = (req, res, next) => {

  console.log(`[LOG] Petición recibida: ${req.method} ${req.url}`);

  next(); // Pasa al siguiente middleware o controlador

};

🔐

¿Para qué usamos Variables de Entorno (`.env`)?

En el desarrollo de software profesional, las aplicaciones se ejecutan en múltiples entornos (desarrollo local, pruebas, producción en la nube). Cada entorno requiere credenciales y configuraciones diferentes (puertos, claves secretas de JWT, credenciales de bases de datos).

Las Variables de Entorno permiten separar la configuración del código fuente. Con la librería dotenv leemos estos valores seguros desde un archivo oculto .env sin exponer contraseñas en GitHub.

# Acceso en Node.js mediante process.env

const puerto = process.env.PORT || 3000;

3. Arquitectura Limpia (Clean Architecture) en Detalle

Cómo desacoplamos las reglas de negocio, las peticiones HTTP y la base de datos para construir software profesional y mantenible.

🏛️ El Fundamento de la Arquitectura Limpia en Express

Evitamos el "código espagueti" (donde todo está mezclado en un solo archivo). La Arquitectura Limpia organiza el proyecto en capas concéntricas con responsabilidades estrictas, aplicando principios SOLID:

1. Capa HTTP (Controllers & Routes)

Maneja la comunicación con el cliente web o móvil. Reciben parámetros, validan códigos HTTP (200, 400, 500) y llaman a los servicios. Desconocen por completo la base de datos.

2. Capa de Negocio (Services)

Contiene las reglas del SENA (ej: validar que el inventario entregado por el guarda sea aceptado por el instructor). Es totalmente independiente del framework Express.

3. Capa de Datos (Models & Repositories)

Interactúan con la base de datos relacional mediante ORM (Sequelize o Prisma), aislando las consultas SQL del resto de la aplicación.

4. Scaffold Paso a Paso: `npm init`, Dependencias y Creación de Archivos

Procedimiento exacto ejecutado en la terminal para inicializar el proyecto y estructurar los directorios de Clean Architecture.

📦

Paso 1: Ejecutar `npm init` y entender el `package.json`

Al ejecutar npm init -y en la terminal, Node.js genera el archivo package.json. Este archivo es el DNI del proyecto y contiene:

  • Metadatos: Nombre del proyecto, versión, autor y descripción.
  • Main: Archivo principal de entrada (ej: server.js).
  • Scripts: Comandos personalizados (ej: "start": "node server.js" o "dev": "nodemon server.js").
  • Dependencies: Librerías instaladas necesarias para que el sistema funcione.
⚡

Comandos de Instalación de Dependencias

Instalamos Express, Dotenv y Cors para producción, junto con Nodemon como dependencia de desarrollo para reiniciar el servidor automáticamente al guardar cambios:

# 1. Crear directorio y entrar

mkdir control-labs-api && cd control-labs-api

# 2. Inicializar package.json

npm init -y

# 3. Instalar librerías de producción

npm install express dotenv cors

# 4. Instalar Nodemon como devDependency

npm install -D nodemon

📁 Paso 2: Estructura de Directorios y Explicación de Archivos Creados

Clean Architecture Scaffold

Ejecutamos en terminal la creación de carpetas organizadas por capas y explicamos detalladamente la responsabilidad de cada archivo que contendrán:

src/config/

Aloja la conexión a la base de datos (Sequelize/Prisma) y configuraciones iniciales de terceros como Google OAuth.

src/controllers/

Controladores HTTP. Reciben peticiones de las rutas, llaman al servicio correspondiente y devuelven respuestas JSON al cliente.

src/services/

Lógica de negocio pura. Contiene las validaciones de préstamos, reglas de inventario del SENA y cálculos de reportes.

src/models/

Modelos relacionales de la base de datos (User, Room, Loan, InventoryItem) definidos en el ORM.

src/middlewares/

Funciones intermedias para validar tokens JWT, control de acceso por roles (RBAC) y manejo centralizado de errores.

src/routes/

Enrutadores modulares de Express. Mapean endpoints REST (ej: /api/v1/loans) hacia sus controladores.

src/app.js

Núcleo de Express. Configura middlewares globales (cors, json) y registra las rutas principales de la API.

server.js

Punto de entrada HTTP raíz. Carga dotenv, importa app.js y pone a escuchar el servidor en el puerto.

.env & .gitignore

Variables de entorno sensibles y exclusión estricta de node_modules y .env para Git.

6. Backlog de Historias de Usuario con Criterios de Aceptación

Requerimientos funcionales detallados para el desarrollo progresivo a lo largo de las 9 semanas.

HU-01: Autenticación con Google (Gmail) y Registro de Usuarios Prioridad: Alta

Como usuario del SENA, quiero iniciar sesión utilizando mi cuenta de correo institucional de Google (Gmail), para acceder de manera segura sin contraseñas adicionales.

Criterios de Aceptación:

  • El botón de inicio de sesión debe redirigir al flujo oficial de autenticación de Google OAuth 2.0.
  • El sistema debe validar el dominio institucional y asignar por defecto el rol de Instructor/Guarda.
  • Al autenticarse, el backend genera un token JWT firmado con el ID, correo y rol.
HU-02: Registro de Préstamo de Sala (Rol Guarda) Prioridad: Crítica

Como Guarda de seguridad, quiero registrar en el sistema los datos completos de entrega de la sala, para dejar constancia legal y física.

Criterios de Aceptación:

  • Endpoint POST /api/v1/loans protegido con JWT de Guarda.
  • Debe recibir: aula, numeroPC, mouse, teclados, cargador, fechaHoraRecibido, numeroTVs, controlTV, instructorRecibe, telefono, nombreGuardaEntrega.
  • Estado inicial: PENDIENTE_APROBACION.
HU-03: Aceptación de Inventario (Rol Instructor) Prioridad: Crítica

Como Instructor SENA, quiero revisar el reporte de inventario registrado por el guarda y aceptarlo, para confirmar recepción a entera satisfacción.

Criterios de Aceptación:

  • Endpoint PUT /api/v1/loans/:id/accept exclusivo para el rol Instructor.
  • El instructor verifica el listado de PCs, mouses, teclados, cargadores y control de TV.
  • Al confirmar, el estado cambia a APROBADO_Y_FIRMADO.
HU-04: Historial con Filtros por Salón y Fechas & Dashboard Prioridad: Media

Como Administrador o Instructor, quiero consultar un historial de préstamos filtrando por aula y rango de fechas, y visualizar métricas en un Dashboard.

Criterios de Aceptación:

  • Endpoint GET /api/v1/loans/history?room=302&startDate=2026-06-01&endDate=2026-06-30.
  • Endpoint GET /api/v1/dashboard/metrics que retorna contadores globales.

7. Desglose Detallado del Código: ¿Qué contienen `server.js` y `app.js`?

Comprende la separación de responsabilidades entre el arranque del servidor HTTP y la configuración del framework Express.

🚀

¿Qué hace `server.js`? (El Arranque HTTP)

Es el punto de entrada exclusivo de la aplicación. Su única responsabilidad es:

  • Cargar el archivo .env utilizando dotenv/config.
  • Importar la aplicación ya configurada desde src/app.js.
  • Poner a escuchar el servidor HTTP en el puerto definido en las variables de entorno (PORT).
⚙️

¿Qué hace `src/app.js`? (La Configuración Express)

Configura el núcleo de Express sin iniciar puertos (ideal para pruebas unitarias y de integración):

  • Inicializa la instancia de Express (const app = express();).
  • Configura middlewares globales como cors() y express.json() para parsear JSON.
  • Define las rutas principales de la API y el middleware de control de errores.
📁 src/app.js & server.js Express Server 
// 📁 server.js (Punto de entrada HTTP)
require('dotenv').config();
const app = require('./src/app');

const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {
  console.log(`🚀 Servidor ControlLabs corriendo en http://localhost:${PORT}`);
});

// 📁 src/app.js (Configuración de Express)
const express = require('express');
const cors = require('cors');

const app = express();

app.use(cors());
app.use(express.json());

// Health Check Endpoint
app.get('/api/v1/health', (req, res) => {
  res.status(200).json({
    status: 'success',
    message: 'ControlLabs API operando correctamente',
    timestamp: new Date().toISOString()
  });
});

module.exports = app;
